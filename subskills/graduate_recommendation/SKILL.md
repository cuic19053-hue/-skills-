# 保研推免申请书 SKILL（v2.0）

> 版本说明：v2.0 引入 PARE 框架、四档字数版本化、推荐信代写流程、导师套磁 SOP、系统填报流程、英语成绩替代策略等 16 项升级。

## §0 适用场景与渠道分流

### 0.1 适用人群与申请类型

本 skill 用于生成保研推免申请书，适用范围：

- 大三学生申请外校或本校研究生推免资格
- 三种渠道任一：夏令营、预推免、九推
- 申请方向：学术型硕士 / 专业型硕士 / 直博

### 0.2 保研推免 vs 考研

| 维度 | 保研推免 | 考研 |
|------|----------|------|
| 入口 | 本校推免资格 + 目标院校接收 | 全国统考 |
| 时间线 | 大三下至大四上 | 大四上 12 月统考 |
| 材料重点 | 学业 + 科研 + 匹配度 + 导师套磁 | 初试分数 + 复试表现 |
| 申请书性质 | 自荐材料 + 个人陈述 + 推荐信 | 复试简历 |
| 评审节奏 | 短时间多投递，匹配度优先 | 一校一志愿 |
| 关键时间 | 夏令营 6 月起 / 预推免 8 月起 / 九推 9.28 起 | 12 月统考 |

### 0.3 三渠道分流决策（重点）

不同渠道的材料形式、签字盖章要求、考核形式均不同，须按渠道分流处理（详见 §11）：

| 渠道 | 时间窗口 | 适合人群 | 材料形式 | 关键节点 |
|------|----------|----------|----------|----------|
| 夏令营 | 5~7 月 | GPA 前 10% 优秀生 | 纸质邮寄为主 | 截止前 7 天寄出 |
| 预推免 | 8~9 月 | 错过夏令营或夏令营未拿优营 | 系统填报 + 电子上传 | 截止前 5 天完成系统填报 |
| 九推 | 9.28~10.20 | 已有 offer 捡漏或全程未拿 offer | 极简系统填报 | 当天决策，材料极简 |

渠道选择实战建议详见 §11.5。

### 0.4 触发与不触发条件

**触发**：用户提到"保研""推免""夏令营申请""预推免""九推""研究生推免""保研申请书""保研个人陈述""推荐信代写""导师套磁"任一关键词时激活。

**不触发**：用户明确说"考研报名表""研究生复试简历"——属其他 skill 范围。

### 0.5 工作流程总览（五阶段）

**阶段 1：信息采集（30~50 分钟）**
按 §3 信息采集清单分批采集，先采学业硬指标，再采科研软实力，最后采申请信息、推荐信与导师沟通进度。每采完一类即复述确认。

**阶段 2：导师方向调研与套磁（与阶段 1 并行，1~2 周）**
按 §7.2 导师方向调研 SOP 完成 5~10 篇代表作阅读 + 1 篇代码复现 + 3 个问题整理，按 §7.3 套磁邮件 SOP 发出首封邮件。

**阶段 3：栏目内容撰写（60~90 分钟）**
按 §1 三段结构撰写个人陈述（核心），按 §5/§6 规范撰写学业与科研栏目，按 §8 完成推荐信代写初稿。

**阶段 4：docx 生成（5 分钟）**
调用 build.py 生成 docx，自动应用统一格式标准。

**阶段 5：签字盖章与提交（按 §9 §10 时间节点）**
按渠道决定签字盖章方式（§9），按时间节点完成推荐信签字、教务处盖章、材料合并（§10）。

**禁止行为**：
- 不替用户编造数据（GPA、排名、论文级别必须真实）
- 不套用网络模板（个人陈述一旦套用直接淘汰）
- 不省略推荐信情况栏（即使推荐信未寄出也要写明推荐人信息）
- 不在科研经历栏只写"参与"（必须含 PARE 四要素）
- 不长篇大论家庭背景（除非与研究方向直接相关）
- 不替用户虚构导师沟通进度（advisor_contact_status 须如实标注）

## §1 三段结构（业界主流版）

### 1.1 结构调整说明

**v1.0 旧结构（错位）**：为什么选方向 / 为什么选学校 / 研究生计划 — 选校理由与研究生计划割裂，逻辑不顺。

**v2.0 新结构（业界主流）**：学术基石 → 实践历程 → 未来展望，三段一气呵成。

| 段号 | 段名 | 内容要点 | 字数占比 |
|------|------|----------|----------|
| 第一段 | 学术基石 | 学业硬指标 + 选方向动机（含 PARE 中的 Effect 维度过渡） | 35~40% |
| 第二段 | 实践历程 | 科研经历详写（PARE 完整四要素）+ 竞赛/学生工作简述 | 35~40% |
| 第三段 | 未来展望 | 选校理由 + 导师对接 + 研究生计划 + 职业规划 | 25~30% |

### 1.2 第一段：学术基石（学业 + 选方向动机）

**核心要素**：学业硬指标概览 → 选方向的真实契机（具体项目/课程/论文）→ PARE 的 Effect（对研究方向的核心认识）→ 自然过渡到第二段。

**句式骨架**：
> 本科前 6 学期 GPA [X.XX/4.0]，专业排名 [X/N（前 X%）]，加权 [XX.X/100]，CET-6 [XXX 分]。我对 [研究方向] 的兴趣，并非源于一时冲动，而是在 [项目名] 中连续投入 [X 个月] 后逐步确认的研究选择。在该项目中，我 [PARE 简述]，这一过程让我意识到 [对方向的核心认识]——这一认识将成为我研究生阶段的起点问题。

**禁忌**：
- "从小就对 XX 充满兴趣"——评审查的是本科 4 年的真实投入
- "贵校是我梦寐以求的学府"——空话
- 长篇大论家庭背景——除非与研究方向直接相关
- 只列课程成绩——课程是基础，不是方向选择的契机
- 把学业硬指标罗列成清单——应融入叙述，不要写简历体

### 1.3 第二段：实践历程（科研经历详写）

**核心要素**：用 PARE 框架展开 2~3 个核心科研经历（按 §6 主次排序原则选），每个经历 P-A-R-E 四要素齐全，竞赛与学生工作简述。

**句式骨架**：
> 在确认方向后，我系统推进了以下研究工作：第一段经历 [PARE 详述，150~200 字]；第二段经历 [PARE 详述，150~200 字]。此外，我参加 [竞赛] 获 [奖项]，担任 [学生工作]，这些经历锻炼了我的 [能力]。

**PARE 单经历模板**：
- **P（Problem）**：项目要解决的具体问题（如"低资源场景下意图识别准确率卡在 82%"）
- **A（Action）**：你做了什么，含技术栈与代码量（如"基于 PyTorch 实现 3000 行对比学习模块"）
- **R（Result）**：量化产出（如"准确率提升至 89%（+7pp），论文投 EMNLP 2024"）
- **E（Effect）**：对研究方向的认识与下一步影响（如"让我认识到表征学习是 NLP 核心问题，下一步聚焦低资源鲁棒表征"）

### 1.4 第三段：未来展望（选校 + 导师对接 + 研究生计划 + 职业规划）

**核心要素**：选校理由（含具体导师与平台）+ 已建立的导师对接进度 + 研究生三步计划（研一/研二/研三）+ 长期职业规划。

**句式骨架**：
> 选择 [学校] 不是因为 [排名/名气]，而是因为 [具体导师] 在 [具体问题] 上的工作直接回应了我本科研究中尚未解决的 [具体痛点]。我已与 [导师] 就 [具体论文名] 进行 [N 次] 邮件沟通，[沟通进展]。若能进入贵校 [实验室] 深造，我计划在研一完成 [课程清单] 与 [文献调研 X 篇]，在研二围绕 [具体研究问题] 推进实验，预期产出 [论文/系统量化指标]，长期目标是 [一句话职业规划]。

**禁忌**：
- "梦寐以求""倍感荣幸"——空话
- 不提具体导师——评审认为未做功课
- 不提具体数据——评审怀疑功课不深
- "努力学习""刻苦钻研"——空话
- 研究生计划不提具体方向与产出——评审无法评估可行性

### 1.5 三段衔接技巧

- 第一段尾句引出第二段："上述学业基础与方向认识，驱动我系统推进了以下研究工作..."
- 第二段尾句引出第三段："基于上述实践积累，我明确了下一步研究方向，并据此选择目标院校..."
- 不用"综上所述""总而言之"等机械过渡词。

### 1.6 三段比例与字数控制

- 三段比例默认 4:4:3（1000~1500 字版）或 2:2:1（500 字版）
- 字数四档详见 §2
- 字数 <800：评审认为投入不够
- 字数 >1800：评审没时间看，重点被稀释

## §2 字数四档版本化适配表

### 2.1 四档版本总表

不同院校对个人陈述字数要求差异大，本 skill 提供四档版本化适配（**build.py 须同步更新支持 `word_count_version` 字段**）：

| 版本 | 三段比例 | 适用院校 | 三段字数分配 | 是否含自我评价段 |
|------|---------|----------|--------------|------------------|
| 500 字版 | 2:2:1 | 211 院校、普通 985 短材料 | 200:200:100 | 否 |
| 1000 字版 | 4:4:2 | 普通 985 标准材料 | 400:400:200 | 否 |
| 1500 字版 | 4:4:3 或 5:4:3 | 清北复交等顶尖 985 | 600:600:300 | 否 |
| 1800 字版 | 5:4:4 | 中科院系统、部分直博项目 | 600:500:450:250 | 是（追加自我评价段） |

### 2.2 字段定义（build.py 须同步更新）

```json
{
  "word_count_version": "1500",  // 500 | 1000 | 1500 | 1800
  "personal_statement": {

    "paragraph_2": "...",  // 实践历程
    "paragraph_3": "...",  // 未来展望
```

### 2.3 500 字版（211 院校适配）

**适用**：211 院校、部分 985 短材料要求。

**三段字数分配**：200:200:100

**撰写要点**：
- 第一段（200 字）：学业硬指标 1 句 + 选方向动机 1 个事件 + Effect 1 句
- 第二段（200 字）：1 个核心科研经历 PARE 简版（每要素 1 句）
- 第三段（100 字）：选校理由 + 研究生计划各 1 句

**示例骨架**：
> 本科前 6 学期 GPA 3.92/4.0，专业排名 1/87（前 1.1%）。我对 NLP 的兴趣源于大二大创项目《XX 法律问答系统》中连续投入 12 个月的经历，让我认识到表征学习是 NLP 核心问题。
>
> 该项目中，我针对意图识别准确率卡在 82% 的问题，基于 PyTorch 实现对比学习模块 3000 行，准确率提升至 89%（+7pp），论文投 EMNLP 2024。这段经历让我聚焦低资源鲁棒表征方向。
>
> 选择 XX 大学是因为 XX 老师在对比学习方向的工作直接回应了上述痛点。研究生阶段计划研一补强数学基础，研二在低资源表征方向产出 CCF-B 论文 1 篇。

### 2.4 1000 字版（普通 985 适配）

**适用**：多数普通 985 院校标准材料要求。

**三段字数分配**：400:400:200

**撰写要点**：
- 第一段（400 字）：学业硬指标 + 选方向动机 + Effect 详细展开
- 第二段（400 字）：1~2 个核心科研经历 PARE 完整版
- 第三段（200 字）：选校理由 + 研究生计划简版

### 2.5 1500 字版（清北复交适配）

**适用**：清华、北大、复旦、上交、浙大等顶尖 985。

**三段字数分配**：600:600:300

**撰写要点**：
- 第一段（600 字）：学业硬指标 + 选方向动机 + 本科相关课程 + Effect
- 第二段（600 字）：2~3 个核心科研经历 PARE 完整版 + 竞赛与学生工作简述
- 第三段（300 字）：选校理由 + 导师对接 + 研究生三步计划 + 职业规划

### 2.6 1800 字版（中科院系统、直博适配）

**适用**：中科院各研究所、部分高校直博项目。

**四段字数分配**：600:500:450:250（追加自我评价段）

**撰写要点**：
- 第一段（600 字）：学术基石（同 1500 字版）
- 第二段（500 字）：实践历程（核心经历）
- 第三段（450 字）：未来展望（含详细研究计划）
- 第四段（250 字）：自我评价段（自我认知 + 不足 + 改进方向 + 适配性陈述）

**自我评价段模板**：
> 综上，我具备 [3 个核心优势：学业基础/科研经历/方向匹配] 三方面基础，但也存在 [1~2 个真实不足：如数学基础/编程效率/英语口语]。研究生阶段我计划通过 [具体改进措施] 系统补强。我相信 [目标院校] 的 [具体平台/导师] 能为我提供最佳成长环境，我也将以最大热情投入研究工作。

### 2.7 字数版本选择决策树

```
目标院校要求字数？
├─ ≤500 字 → 选 500 字版（211 院校）
├─ 500~1000 字 → 选 1000 字版（普通 985）
├─ 1000~1500 字 → 选 1500 字版（清北复交）
└─ >1500 字 → 选 1800 字版（中科院/直博）
```

### 2.8 字数自检脚本（按版本动态校验）

```python
import re
import json

with open('data.json', encoding='utf-8') as f:
    data = json.load(f)

version = data.get('word_count_version', '1500')
limits = {'500': (450, 550), '1000': (900, 1100),
          '1500': (1400, 1600), '1800': (1700, 1900)}

text = data['personal_statement']['paragraph_1'] + \
       data['personal_statement']['paragraph_2'] + \
       data['personal_statement']['paragraph_3']
if version == '1800':
    text += data['personal_statement'].get('paragraph_4', '')

cn = len(re.findall(r'[\u4e00-\u9fff]', text))
lo, hi = limits[version]
assert lo <= cn <= hi, f'字数 {cn} 不在 {version} 字版区间 [{lo}, {hi}]'
print(f'✅ 字数 {cn} 符合 {version} 字版要求')
```

## §3 信息采集清单

### 3.1 学业硬指标（必采）

| 字段 | 说明 | 示例 |
|------|------|------|
| gpa_6sem | 前 6 学期 GPA（含分母） | 3.92/4.0 |
| weighted_avg | 加权平均分 | 91.5/100 |
| rank | 专业排名（X/N） | 1/87 |
| rank_percent | 排名百分比 | 前 1.1% |
| main_courses | 主修课程（含学期/学分/成绩） | 数组 |
| scholarships | 奖学金（时间/名称/级别） | 数组 |
| cet4 | CET-4 成绩 | 580 |
| cet6 | CET-6 成绩 | 580 |
| toefl | TOEFL 成绩（如有） | 105 |
| ielts | IELTS 成绩（如有） | 7.5 |
| recommend_qualified | 是否已取得本校推免资格 | 是/否 |
| minor_degree | 辅修/双学位成绩（如有） | 数组 |

**追问话术**：
- "你前 6 学期 GPA 是多少？分母是 4.0 还是 5.0？"
- "专业排名 X/N，N 是专业总人数还是同年级人数？"
- "CET-6 考了几次？最高分多少？"
- "奖学金请按时间倒序列出，注明级别（国家/省/校/院）"
- "有辅修或双学位吗？成绩如何？"（决定英语成绩替代策略，见 §5.3）

### 3.2 科研软实力（必采）

## §4 PARE 框架与 STAR 对照

### 4.1 为什么用 PARE 而非 STAR

STAR（Situation/Task/Action/Result）是求职简历通用框架，但**保研评审更看重"研究认识与下一步方向"**，而 STAR 的 Result 维度只到"产出"，缺少"对研究方向的影响"这一关键维度。

**PARE = Problem → Action → Result → Effect**，比 STAR 多一个 Effect 维度，让科研经历自然过渡到方向选择动机，是保研个人陈述的最佳实践框架。

### 4.2 PARE 四要素详解

| 要素 | 含义 | 撰写要点 | 字数占比 |
|------|------|----------|----------|
| P (Problem) | 项目要解决的具体问题 | 必须具体到数字/瓶颈/痛点，不写"研究 XX 问题" | 25% |
| A (Action) | 你做了什么，含技术栈与代码量 | 必须含技术栈名+量化工作量（代码行数/实验次数/数据量） | 35% |
| R (Result) | 量化产出 | 必须可量化：准确率/数据集规模/论文级别/专利数 | 25% |
| E (Effect) | 对研究方向的认识与下一步影响 | 必须包含"我认识到 XX"与"下一步聚焦 XX"两层 | 15% |

### 4.3 STAR ↔ PARE 对照表

| STAR | PARE | 差异说明 |
|------|------|----------|
| Situation（情境） | （并入 Problem） | PARE 将情境与问题合并，更聚焦 |
| Task（任务） | Problem（要解决的具体问题） | PARE 强调"问题"而非"任务"，更符合科研语境 |
| Action（行动） | Action（你做了什么） | 一致，但 PARE 要求量化技术栈与代码量 |
| Result（结果） | Result（量化产出） | 一致，PARE 强调可量化 |
| — | Effect（对研究方向的认识） | **PARE 独有**，让经历自然过渡到方向动机 |

### 4.4 PARE 完整示例

**示例：低资源对话理解项目**

> **P（Problem）**：在 XX 教授课题组"低资源场景下的对话理解"项目中，我发现现有基线模型在中文多轮对话意图识别上的准确率仅 82%，主要瓶颈在于标注数据稀缺导致表征学习不充分。
>
> **A（Action）**：作为数据构建与模型训练负责人，我主导完成三件事：①构建含 5000 条多轮对话的中文数据集（独立完成标注规范文档 1 份）；②复现 3 个基线模型（BERT、RoBERTa、DeBERTa）并基于 PyTorch 实现 3000 行对比学习模块；③完成 50+ 组对比实验，使用 A100 GPU 800 卡时。
>
> **R（Result）**：准确率从 82% 提升至 89%（+7pp），相关成果以第一作者投 EMNLP 2024（在审），申请发明专利 1 项（实质审查中）。
>
> **E（Effect）**：这一经历让我认识到：低资源场景下的鲁棒表征是 NLP 核心问题之一，下一步我计划聚焦"对比学习与知识蒸馏融合"方向，这正是我希望在研究生阶段深入突破的起点问题。

### 4.5 PARE 反例（禁用）

- **反例 1**（缺 P）："我参与了 XX 项目，做了很多工作，发表了论文。"
- **反例 2**（A 不量化）："我负责模型训练，使用了深度学习框架。"
- **反例 3**（R 不可量化）："项目取得了一定成果，获得了导师认可。"
- **反例 4**（缺 E，无法过渡到方向）："准确率提升 7pp，论文投 EMNLP 2024。"

### 4.6 PARE 与三段结构的对应

- §1 第一段（学术基石）：使用 PARE 的 E 维度（对方向的认识）作为方向选择动机的依据
- §1 第二段（实践历程）：完整展开 2~3 个经历的 PARE 四要素
- §1 第三段（未来展望）：PARE 的 E 维度引出"下一步聚焦 XX 方向"自然过渡到选校与导师对接

## §5 学业部分撰写规范

### 5.1 学业硬指标写法

- GPA 必须含分母："3.92/4.0"，不写"3.92"
- 排名必须含基数："专业排名第 1/87"，不写"专业第一"
- 排名百分比精确到小数点后一位："前 1.1%"
- 主修课程仅列专业核心课与高分课程（≥85 分），不列公选课
- 奖学金注明级别与覆盖率："国家奖学金（专业前 1%）"
- 加权平均分与 GPA 同时给出："GPA 3.92/4.0，加权 91.5/100"
- 推免资格写明："已取得本校 2026 届推免资格（2025.09 公布）"

### 5.2 学业段在个人陈述中的展开

学业硬指标在个人陈述第一段（学术基石）中应**融入叙述**，不要写成简历体清单：

**正例**：
> 本科前 6 学期 GPA 3.92/4.0（专业排名第 1/87，前 1.1%），加权 91.5/100，连续 4 学期获专业第一。我在《自然语言处理》（96 分）与《深度学习》（94 分）中系统建立了 NLP 理论基础，这为我后续开展对比学习研究提供了必要的数学与工程准备。

**反例**（简历体，禁用）：
> 学业情况：GPA 3.92/4.0，排名 1/87，前 1.1%。主修课程：自然语言处理 96 分，深度学习 94 分，机器学习 95 分。

### 5.3 英语成绩替代策略决策树（重点）

不同英语成绩组合对应不同写法，按以下决策树处理：

```
CET-6 成绩？
├─ ≥500 → 只写 CET-6（已属优秀，无需替代）
├─ 425~500
│  ├─ 有 IELTS ≥6.5 或 TOEFL ≥95 → 用 IELTS/TOEFL 替代 CET-6
│  ├─ 有 IELTS <6.5 或 TOEFL <95 → 写 CET-6 + 注明备考 IELTS 计划
│  └─ 无 IELTS/TOEFL → 写 CET-6 + 注明备考 IELTS 计划（"计划 2025.10 参加 IELTS，目标 7.0"）
├─ <425 或未过
│  ├─ CET-4 ≥550 且学校允许 → 视学校要求，部分允许只写 CET-4
│  ├─ 有 IELTS ≥6.5 或 TOEFL ≥95 → 用 IELTS/TOEFL 替代
│  └─ 无任何替代 → 风险极高，建议先补考 CET-6 再申请
└─ 有辅修/双学位 → 可附辅修英语成绩替代（部分院校认可）
```

**写法示例**：

| 情形 | 写法 |
|------|------|
| CET-6 580，无其他 | "CET-6 580" |
| CET-6 460 + IELTS 7.0 | "IELTS 7.0（2024.11），CET-6 460" |
| CET-6 460 无替代 | "CET-6 460，计划 2025.10 参加 IELTS（目标 7.0）" |
| CET-4 580，CET-6 未过 | "CET-4 580（CET-6 备考中，预计 2025.06 通过）" |
| CET-6 580 + TOEFL 105 | "CET-6 580 / TOEFL 105（2024.10）" |

**禁忌**：
- 不写"CET-6 通过"（必须写具体分数）
- 不写"英语良好"（必须写证书）
- 不隐瞒低分 CET-6（评审会查原件）
- 不虚构 IELTS/TOEFL 成绩（须有成绩单佐证）

### 5.4 主修课程成绩表规范

主修课程成绩表 4 列：学期 / 课程名 / 学分 / 成绩。按学期正序排列，仅列专业核心课与高分数课程（10~15 门）。

| 学期 | 课程名 | 学分 | 成绩 |

| 第 1 学期 | C 语言程序设计 | 3 | 96 |
| 第 2 学期 | 数据结构 | 4 | 94 |

| 第 4 学期 | 操作系统 | 4 | 93 |
| 第 5 学期 | 机器学习 | 3 | 95 |
| 第 5 学期 | 自然语言处理 | 3 | 96 |
| 第 6 学期 | 深度学习 | 3 | 94 |

### 5.5 奖学金表规范

奖学金表 3 列：时间 / 奖项全称 / 级别。按时间倒序，注明级别（国家/省/校/院）。

### 6.4 夏令营面试预测与科研经历选择（重点）

**核心原则**：个人陈述详写的科研经历必须能扛 10 分钟深问，不熟的不写。

**经历选择标准**：
- 选 2~3 个最熟悉的科研经历详写（按 §6.1 主次排序）
- 每个经历预判老师可能问的 3 个深挖问题：
  1. **技术细节**：你用的对比学习损失函数是什么？为什么选 InfoNCE 而非 Triplet？
  2. **对比基线**：你的 +7pp 是相对哪个基线？有没有跟 SOTA 对比？
  3. **改进思路**：如果数据再减少 50%，你的方法还能 work 吗？为什么？

**经历选择反例**：
- 只挂名未实际参与的项目（被问深就露馅）
- 只跑过 demo 未深入理解的项目（被问原理就答不上）
- 老师主导、自己只做辅助的项目（被问"你的贡献"就尴尬）

**自查清单**（每个详写的经历必须能回答）：
- □ 这个项目的核心问题是什么？（P）
- □ 你具体做了哪些工作？用了哪些技术？写了多少代码？（A）
- □ 量化产出是多少？跟基线/SOTA 对比如何？（R）
- □ 你对这个方向的核心认识是什么？下一步改进方向？（E）
- □ 如果老师追问 3 个技术细节，你能流畅回答吗？

### 6.5 科研经历量化表达参考

| 类别 | 量化表达示例 |

| 准确率提升 | 准确率从 82% 提升至 89%（+7pp） |

| 文献调研量 | 系统调研近 3 年顶会论文 50 篇 |
| 代码量 | 独立实现 3000+ 行 PyTorch 代码 |
| 实验次数 | 完成 50+ 组对比实验 |

| 资源占用 | 使用 A100 GPU 800 卡时 |
| 样本规模 | 处理 100 万条原始文本 |

### 6.6 科研经历与个人陈述呼应

个人陈述第二段提到的科研经历，必须在科研经历栏目有详细记录；科研经历栏目的高亮项目，必须在个人陈述中提到。两者相互印证，避免评审质疑真实性。

**呼应示例**：
- 个人陈述："主持国家级大创《基于对比学习的法律问答系统》，准确率提升 7pp"
- 科研经历表：项目名称 + 级别 + 角色 + 起止 + 产出（7pp 与论文投稿）
- 附件清单：大创立项书 + 结题证明 + EMNLP 投稿确认邮件

## §7 选校理由与导师对接

### 7.1 选校理由撰写规范

选校理由在第三段（未来展望）中展开，必须包含三点：

1. **该校在该方向的具体优势数据**（论文数/师资数/平台名）
2. **与拟申请导师的具体联系**（邮件次数/方向契合点/老师建议）
3. **平台/资源/课程体系的具体优势**（实验室名/设备型号）

**句式模板**（详见 §15 金句模板）：
> 选择 [学校] 不是因为 [排名/名气]，而是因为 [具体导师] 在 [具体问题] 上的工作直接回应了我本科研究中尚未解决的 [具体痛点]。

**正例**：
> 选择 XX 大学不是因为在 CS Rankings 排名前列，而是因为 XX 教授在对比学习与知识蒸馏融合方向的工作直接回应了我本科研究中尚未解决的"低资源场景下表征不充分"痛点。我已与 XX 教授邮件沟通 3 次，老师建议我提前阅读其 2024 年 ACL 论文并复现核心代码，目前已完成 80% 复现进度。此外，贵校 XX 国家重点实验室配备 A100 GPU 集群 8 卡节点，能提供本方向所需的大规模预训练计算资源。

### 7.2 导师方向调研 SOP（重点）

个人陈述第三段提到导师沟通前，必须先完成导师方向调研。**调研不充分就套磁 = 把不熟的导师写进 PS = 面试翻车**。

**5 步调研流程**：

1. **读导师近 3 年代表作 5~10 篇**（含 1 篇精读）
   - 来源：导师个人主页 / Google Scholar / DBLP
   - 精读 1 篇：完整读 + 整理研究问题/方法/创新点/局限

2. **复现其中 1 篇核心代码**
   - GitHub 开源则跑通（README + 环境 + 数据 + 复现结果）
   - 不开源则手写复现（按论文方法实现核心模块）
   - 记录复现进度（如"已复现 80%，剩余 20% 因数据未公开待解决"）

3. **整理 3 个可深入问题**
   - 问题须具体到论文中的某个方法/实验/局限
   - 反例："老师您的工作很有启发"（空话）
   - 正例："您在 ACL 2024 论文中提到对比学习的温度参数 τ 设为 0.07，但消融实验未给出 τ 的敏感性分析，请问后续工作中是否做过 τ 的系统调参？"

4. **邮件中提 1 个具体问题**
   - 从 3 个问题中选最具体、最容易回答的 1 个
   - 问题字数控制在 30 字以内
   - 不要在首封邮件问太深的问题（老师没时间回）

5. **根据回复调整个人陈述第二段匹配点**
   - 老师回复提到的新论文/方向 → 补进 PS 第三段导师对接段
   - 老师建议阅读的论文 → 阅读 + 在 PS 中提到"已阅读老师推荐的 XX 论文"
   - 老师不回复 → 按 §7.4 应对策略处理

### 7.3 导师套磁邮件 SOP（重点）

**时间节点**：
- 夏令营前 1~2 个月（4~5 月）发首封套磁信
- 预推免前 2~3 周（8 月中下旬）发首封套磁信
- 九推不建议套磁（时间太紧，老师来不及回）

**邮件结构**（共 5 段，总字数 200~250 字）：

| 段 | 内容 | 字数 |
|----|------|------|
| 自我介绍 | 姓名/学校/专业/年级 + 申请意向 | 50 字 |
| 学业硬指标 | GPA + 排名 + 英语（一句话） | 30 字 |
| 科研匹配点 | 你读了老师哪篇论文 + 你的相关研究经历 | 80 字 |
| 一个具体问题 | 基于 §7.2 调研整理的具体问题 | 30 字 |
| 礼貌结尾 | 期待回复 + 附件简历 + 致谢 | 10 字 |

**首封模板**：

> 主题：[XX 大学计算机学院夏令营申请咨询] 张三 / [本校] / [申请方向]

### 7.4 老师不回复的 3 步应对

**第 1 步**：等待 7~10 天，不要催
- 老师可能出差/开会/写本子，7 天内不回复属正常

**第 2 步**：发跟进邮件（按 §7.3 跟进模板）
- 跟进邮件中体现"我已读更多老师论文"，证明诚意
- 不要在跟进邮件中重复首封的全部内容

**第 3 步**：仍未回复则放弃该导师，换备选导师
- 同一导师最多发 2 封（首封 + 1 次跟进），第 3 封会被视为骚扰
- 换导师前先检查：是否套磁信写得不好？是否方向不匹配？是否时间太晚？

**advisor_contact_status 字段对应**（build.py 须同步更新）：

| 状态 | 含义 | PS 第三段写法 |
|------|------|---------------|
| not_contacted | 未联系 | 不写导师沟通，只写"拟申请 XX 老师" |
| emailed | 已发邮件未回复 | 写"已发邮件咨询，等待老师回复" |
| replied | 老师已回复 | 写"已与 XX 老师邮件沟通 N 次，老师建议..." |
| met | 已面谈/视频会议 | 写"已与 XX 老师面谈，老师建议..." |

## §8 推荐信代写完整流程

### 8.1 推荐信代写的现实

实际操作中，**多数推荐信由学生代写初稿、老师修改签字**，这是行业惯例（不算造假，因为老师最终签字即代表认可内容）。本 skill 提供完整的 6 步代写流程与初稿模板。

### 8.2 6 步推荐信代写流程

**步骤 1：询问老师是否愿写（话术）**

当面或邮件询问，话术参考：

> XX 老师您好，我是 [姓名]，[课程/项目] 中的学生。我计划申请 [学校] [方向] 推免，希望邀请您为我撰写推荐信。我会提前准备好推荐信素材（含我的成绩、科研经历、性格亮点），如果您方便，也可以由我先起草初稿供您修改，您看是否可行？截止日期是 [日期]，期待老师回复。

**关键点**：
- 必须先问意愿，不能直接发初稿
- 主动提出"先起草初稿供您修改"，减轻老师负担
- 明确截止日期，给老师充分时间

**步骤 2：收集老师视角素材**

整理一份"推荐信素材包"发给老师，包含：
- 你的成绩单（重点标注老师任课/指导课程的成绩）
- 你的科研经历详述（PARE 框架，重点突出在老师指导下的工作）
- 你的性格亮点（3 个具体事例，如"在 XX 项目中连续 3 周加班攻克技术难题"）
- 你的申请方向与目标院校
- 推荐信截止日期与提交方式（纸质/电子）

**步骤 3：以老师口吻写 800~1200 字初稿**

按 §8.3 初稿模板撰写，注意：
- 第一人称用"我"（指老师），不用"该生"
- 评价须具体到事例，不空泛
- 长度 800~1200 字（短了显敷衍，长了老师改起来累）
- 突出"该生在我指导下"的关联性

**步骤 4：截止前 7 天交老师**

给老师留 7 天修改时间，老师可能：
- 直接签字（最理想）
- 修改个别字句后签字（常见）
- 大幅修改后签字（少见，但须预留时间）

**步骤 5：老师修改**

老师修改后，确认最终版本。如老师要求你再调整，及时配合。

**步骤 6：签字（亲签/电子签）**

按 §9 签字/盖章方式决策表处理：
- 电子材料提交：可用电子签（PDF 签名或扫描件）
- 纸质邮寄：必须亲签 + 信封密封 + 推荐人在封口骑缝签字

### 8.3 推荐信初稿模板（含老师口吻范例）

**推荐信初稿模板**（约 1000 字）：

> **推荐信**
>
> 致 [目标院校] 招生委员会：
>
> 我是 [本校] [学院] [职称] [姓名]，作为 [申请人姓名] 同学的 [任课教师/科研导师/班主任]，很高兴为其申请贵校 [方向] 推免项目撰写推荐信。我与 [申请人] 同学自 [时间] 起在 [课程/项目] 中有深入接触，对其学业、科研与性格有全面了解。
>
> **学业表现**：[申请人] 同学学业成绩优异，前 6 学期 GPA [X.XX/4.0]，专业排名 [X/N]，在我任教的 [课程名] 中取得 [XX 分] 成绩，位列全班第 [X]。该生课堂表现积极，多次就 [具体问题] 与我深入讨论，展现出扎实的理论基础与较强的批判性思维。
>
> **科研能力**：自 [时间] 起，[申请人] 同学进入我的课题组，参与 [项目名] 项目。在该项目中，该生 [PARE 简述：针对什么问题，做了什么，量化产出]。值得一提的是，[具体事例：如"该生独立完成对比学习模块 3000 行代码，准确率提升 7pp"]，这一成果以第一作者投 [会议/期刊]。该生在我的指导下，已具备独立开展 [方向] 研究的初步能力。
>
> **性格亮点**：[申请人] 同学 [3 个性格亮点，每个配 1 个具体事例]：
> ① [亮点 1：如"研究态度严谨"]：[事例：如"在 XX 项目中主动复查 3 遍数据集标注，发现并修正 200 处错误"]；
> ② [亮点 2：如"学习能力突出"]：[事例：如"2 周内自学 PyTorch 并投入项目实战"]；
> ③ [亮点 3：如"团队协作良好"]：[事例：如"在 5 人小组中担任技术负责人，协调分工推进项目"]。
>
> **匹配度评估**：基于该生在 [方向] 上的科研积累与对 [目标院校] [导师] 工作的理解，我认为其在贵校 [方向] 深造具有高度匹配性，预期能在 [具体方向] 取得有价值的成果。
>
> 综上，我郑重推荐 [申请人] 同学申请贵校 [方向] 推免项目，希望贵校予以重点考虑。如需进一步了解该生情况，欢迎与我联系。
>
> 推荐人：[姓名]（签字）
> 职称：[职称]
> 单位：[单位]
> 邮箱：[邮箱]
> 电话：[电话]
> 日期：[日期]

### 8.4 推荐信代写注意事项

- **不夸大**：评价须有具体事例支撑，量化指标不超过实际成绩
- **不模板化**：每封推荐信须体现该推荐人与申请人的具体关联
- **不重复**：两封推荐信须从不同角度（如科研导师重科研，任课教师重学业）
- **不造假**：推荐人职称、单位、联系方式必须真实
- **不替老师签字**：必须老师本人签字（亲签或电子签）

### 8.5 推荐信情况栏目规范

申请书 docx 中"推荐信情况"栏目须列 2 位推荐人：

| 推荐人 | 职称 | 关系 | 研究方向 | 联系方式 | 是否已确认 |
|--------|------|------|----------|----------|------------|
| 李教授 | 教授 | 科研导师 | 自然语言处理 | li@xxx.edu.cn | 是 |
| 王副教授 | 副教授 | 任课教师（机器学习） | 机器学习 | wang@xxx.edu.cn | 是 |

如推荐信尚未寄出，注明"推荐信将于 X 月 X 日前由推荐人直接寄送"。

## §9 签字/盖章方式决策表

### 9.1 提交方式与签字盖章对照表

不同提交方式对应不同签字盖章要求，按以下决策表处理：

| 提交方式 | 签字方式 | 密封要求 | 适用渠道 |
|----------|----------|----------|----------|
| 电子材料提交（上传 PDF） | 可用电子签（PDF 签名或扫描件） | 无 | 预推免、九推 |
| 纸质邮寄 | 必须亲签（推荐人手写签名） | 信封密封 + 推荐人在封口骑缝签字 | 夏令营 |
| 老师出差/不在校 | 协调签名时间（见 §9.2 话术） | 提前预约，返校后补签 | 任一渠道 |
| 系统填报型（在线填表） | 系统内电子签或扫描上传 | 无 | 预推免、九推 |

### 9.2 老师出差协调签名话术（3 则）

**话术 1（老师出差前预约）**：
> XX 老师您好，得知您 [日期] 起出差，我的推荐信材料 [日期] 截止，不知您出差前是否方便签字？我可以提前把初稿送到您办公室，您审阅后签字，时间只需 5 分钟。如您出差前不便，我也可等您 [返回日期] 后再签，请老师告知方便时间。

**话术 2（老师出差中协调）**：
> XX 老师您好，打扰您出差。我的推荐信材料 [日期] 截止，如您出差中方便，是否可通过电子签（PDF 签名）方式处理？我可以把初稿发您邮箱，您审阅后用电子签工具签字回传。如不便电子签，我也可以等您 [返回日期] 后当面签字，请老师告知偏好。

**话术 3（老师返程后补签）**：
> XX 老师您好，欢迎返校。我的推荐信材料 [日期] 截止，您出差前未及签字，不知您本周 [具体日期] 是否方便当面签字？我可以把初稿送到您办公室，时间只需 5 分钟。如本周不便，下周 [具体日期] 也可以，请老师告知方便时间。

### 9.3 签字盖章常见问题

**Q1：推荐人坚持亲签但邮寄截止在即？**
A：优先与推荐人协商提前签字时间（按 §9.2 话术）；如确无法亲签，与目标院校招生办沟通是否接受电子签。

**Q2：教务处盖章排队太久？**
A：提前 3 天预约教务处盖章时间（详见 §10 时间节点）；如教务处排队过长，可申请加急（推免材料属加急范围）。

**Q3：学院推免工作小组盖章找不到人？**
A：提前 1 周联系学院推免工作小组（一般是教学秘书），确认盖章时间；如找不到负责人，可请辅导员协调。

**Q4：电子签的推荐信是否被认可？**
A：预推免与九推多数院校接受电子签；夏令营纸质邮寄的院校必须亲签。具体以目标院校招生简章为准。

## §10 时间节点（截止前 5~7 天）

### 10.1 时间节点前置说明

**v1.0 旧时间节点**：提交前 3 天完成 — 过晚，一旦出问题（推荐人出差/教务处排队/材料丢失）无应急时间。

**v2.0 新时间节点**：截止前 5~7 天完成关键节点，预留 1 天应急。

### 10.2 标准时间节点表（以截止日为 T-0）

| 节点 | 时间 | 任务 | 负责方 |
|------|------|------|--------|

| T-7 | 截止前 7 天 | 推荐信签字完成 | 推荐人 |
| T-5 | 截止前 5 天 | 推荐信密封寄出（如纸质邮寄） | 申请人/推荐人 |
| T-5 | 截止前 5 天 | 教务处盖章预约 + 排队完成 | 申请人 |
| T-3 | 截止前 3 天 | 教务处成绩单盖章完成 | 申请人 |
| T-2 | 截止前 2 天 | 所有材料合并 + 扫描 + 命名 | 申请人 |
| T-1 | 截止前 1 天 | 应急预留（处理突发问题） | 申请人 |
| T-0 | 截止日 | 提交（邮寄寄出 / 系统上传 / 现场递交） | 申请人 |

### 10.3 时间节点决策树

```
距截止日还有几天？
├─ ≥14 天 → 按 §10.2 标准时间节点表执行（最佳）
├─ 7~14 天 → 压缩推荐信初稿撰写至 2 天，其他节点不变
├─ 3~7 天 → 推荐信改电子签，教务处加急，材料合并压缩至 1 天
└─ <3 天 → 高风险，建议放弃该批次，准备下一批次
```

### 10.4 时间节点常见风险与应对

| 风险 | 应对 |
|------|------|
| 推荐人出差/生病 | 提前协调签名时间（§9.2），或改电子签 |
| 教务处排队过长 | 提前 3 天预约 + 加急申请 |
| 成绩单盖章被退回（信息有误） | 预留 T-3 至 T-2 时间处理重盖 |
| 推荐信邮寄丢失 | 挂号信 + 留底单 + 跟踪物流 |
| 系统填报截止前崩溃 | 提前 1 天完成填报，截止日只做最后确认 |
| 附件扫描件体积过大 | PDF 压缩工具（如 Smallpdf）压至 10MB 以内 |

### 10.5 提交前 24 小时最终自查

按 §17 红线规则与质检清单逐项核对：
- □ 所有签字完成（申请人 + 推荐人 + 学院盖章）
- □ 所有附件扫描清晰可读
- □ 文件命名符合目标院校要求
- □ 系统填报字段全部填写
- □ 邮寄材料装订顺序正确
- □ 预留 1 份完整电子版备份

## §11 夏令营 vs 预推免 vs 九推材料差异表

### 11.1 三渠道材料差异总表（v2.0 扩充版）

v1.0 旧表只列"录取概率"与"材料侧重点"过浅，v2.0 扩充为 6 列完整对比，覆盖时间/概率/形式/签字/考核：

| 渠道 | 时间 | 录取概率 | 材料形式 | 签字盖章要求 | 考核形式 |
|------|------|----------|----------|--------------|----------|
| 夏令营 | 5~7 月 | 较高（优营基本直录） | 纸质邮寄为主 | 必须亲签 + 信封密封 + 骑缝签字 | 综合活动 + 笔试 + 面试 |
| 预推免 | 8~9 月 | 中等 | 系统填报 + 电子上传 | 电子签即可 | 纯笔试 + 面试 |
| 九推 | 9.28~10.20 | 低（捡漏为主） | 极简系统填报 | 系统内填报，无需纸签 | 系统 + 面试（部分院校无面试） |

### 11.2 夏令营材料准备要点

- 纸质邮寄为主（部分院校接受电子预审），建议顺丰或 EMS，留底单跟踪物流
- 必须亲签（推荐人 + 申请人 + 学院盖章），推荐信须推荐人签字后单独密封 + 封口骑缝签字
- 截止前 5~7 天寄出（预留物流时间）；考核重点为综合活动 + 笔试 + 面试，材料是入场券

### 11.3 预推免系统填报 SOP（重点）

预推免多数院校采用系统填报而非自提交 docx，按以下 SOP 操作：

**步骤 1：登录目标院校研招系统**
- 网址：目标院校研究生院官网 → 推免生报名系统
- 账号：通常用身份证号 + 手机号注册
- 时间：系统开放期通常为 8 月中下旬至 9 月初

**步骤 2：按字段填写（字段映射表对应 SKILL 数据）**

8 类常见字段及对应 SKILL 数据：

| 系统字段 | SKILL 数据字段 | 填写要点 |
|----------|----------------|----------|
| 学习工作信息 | basic_info + academics | 学校/专业/班级/起止时间 |
| 学籍学历 | applicant_college + applicant_major | 学号/学制/培养层次 |
| 户档信息 | basic_info | 户口所在地/档案所在地 |
| 家庭信息 | (新增采集) | 父母姓名/单位/联系方式 |
| 学业成绩 | academics.gpa_6sem + rank + weighted_avg | GPA + 排名 + 加权，须与成绩单一致 |
| 科研成果 | research.papers + patents + projects | 按系统要求分类填写 |
| 个人陈述 | personal_statement | 按字数版本粘贴，注意系统字数限制 |
| 推荐人信息 | recommendations | 推荐人姓名/职称/邮箱/电话 |

**步骤 3：导出 PDF**
- 系统通常支持"生成 PDF"或"打印预览"
- 导出后检查 PDF 格式是否完整（表格/图片/字数）

**步骤 4：签字盖章**
- 申请人签字：亲签或电子签（按系统要求）
- 学院盖章：教务处或学院推免工作小组盖章
- 推荐人签字：电子签即可（预推免多数接受）

**步骤 5：扫描合并**
- 所有需要纸质签字盖章的页面扫描为 PDF
- 按系统要求顺序合并为单个 PDF
- 文件命名：[姓名]_[申请学校]_预推免材料.pdf

**步骤 6：上传系统**
- 上传前检查文件大小（通常 <10MB）
- 上传后下载确认文件可正常打开
- 截图保存上传成功页面作为凭证

### 11.4 九推材料极简化要点

- 系统填报，无需纸质；系统内电子签或无需签字
- 核心材料：身份证 + 学生证 + 成绩单 + 推免资格证明
- 个人陈述通常 500 字以内（按 §2 500 字版）；多数院校不要求推荐信
- 决策时间通常 24 小时内，材料极简

### 11.5 渠道选择的实战建议

| 你的情况 | 推荐渠道 | 备选渠道 |
|----------|----------|----------|
| GPA 前 5% + 有论文 | 夏令营（主投 3~5 所） | 预推免（保底 2~3 所） |
| GPA 前 10% + 有大创 | 夏令营（主投 2~3 所） + 预推免（主投 3~5 所） | 九推（捡漏） |
| GPA 前 20% + 科研较弱 | 预推免（主投 5~8 所） | 夏令营（保底 1~2 所） |
| 全程未拿 offer | 九推（捡漏 5~10 所） | — |

## §12 系统填报型申请表流程

### 12.1 系统填报 vs 自提交 docx

实际操作中，**多数院校采用系统填报而非自提交 docx**。本 skill 生成的 docx 主要用于：
1. 提前撰写与校对内容（系统填报前准备好文字稿）
2. 部分接受自提交 docx 的院校直接使用
3. 个人留档与备查

### 12.2 系统填报 6 步流程

完整流程详见 §11.3 预推免系统填报 SOP（步骤 1~6）。通用补充注意事项：
- 不同院校系统不同，须分别注册；建议用同一邮箱注册所有院校便于管理
- 复制粘贴时注意格式（系统可能不支持富文本）
- 字数限制严格，超字无法保存，建议先在 docx 中按字数版本写好再粘贴
- 不支持导出 PDF 的系统用浏览器"打印 → 另存为 PDF"

### 12.3 系统填报常见坑

- **字数限制**：系统通常严格限制字数（如个人陈述限 1000 字），超字无法保存。建议先在 docx 中写好，再按字数版本粘贴。
- **格式丢失**：系统不支持富文本，复制粘贴会丢失加粗/斜体/缩进，建议用纯文本格式。
- **图片上传**：部分系统要求上传图片（如证件照/成绩单扫描件），注意格式（JPG/PNG）与大小（通常 <2MB）。
- **保存超时**：长时间不操作会自动登出，建议每 10 分钟保存一次。**浏览器兼容**：部分系统仅支持 IE 或特定浏览器，建议提前测试。

## §13 简历与个人陈述分工说明

### 13.1 简历与个人陈述的定位差异

| 维度 | 简历（CV） | 个人陈述（PS） |
|------|------------|----------------|
| 形式 | 一页纸 | 800~1800 字 |
| 内容 | 列硬指标，不展开 | 详细展开 2~3 个核心科研经历 |
| 重点 | GPA/排名/英语/论文/竞赛 | PARE 框架展开科研经历 + 选方向动机 |
| 风格 | 客观陈述 | 主观叙述 |
| 用途 | 评审快速浏览 | 评审深度评估 |
| 附件位置 | docx 第一页或单独提交 | 个人陈述栏 |

### 13.2 简历撰写规范

**一页纸原则**：简历必须控制在一页 A4 纸内，评审没时间翻第二页。

**简历结构**（从上到下）：

1. **个人信息**（5 行）：姓名/性别/出生年月/政治面貌/联系方式
2. **教育背景**（3 行）：学校/专业/GPA/排名/英语
3. **科研经历**（5~8 行）：2~3 个核心项目，每项 1~2 行
4. **论文专利**（3~5 行）：按级别倒序，每项 1 行
5. **竞赛获奖**（2~4 行）：按级别倒序，每项 1 行
6. **学生工作**（1~2 行）：1~2 个主要职务
7. **技能特长**（1~2 行）：编程语言/工具/语言

**简历示例**：

```
张三 | 男 | 2003.05 | 中共党员 | 138XX / zhangsan@xxx.edu.cn

XX 大学 计算机科学与技术 本科（2022.09-2026.06）

  · 准确率从 82% 提升至 89%（+7pp），论文投 EMNLP 2024（在审）
  · 独立实现 3000 行 PyTorch 对比学习模块，使用 A100 GPU 800 卡时

论文专利
[1] XX 法律问答中的对比学习. EMNLP 2024 (CCF-B). 第一作者. 在审.
[2] 基于预训练模型的中文分词. 计算机应用 (中文核心). 第一作者. 已发表.

竞赛获奖

技能特长
Python/PyTorch/HuggingFace Transformers | 英语（CET-6 580 / TOEFL 105）
```

### 13.3 数据一致性要求

**简历与个人陈述的数据必须一致**，评审会交叉核对：

- GPA / 排名 / 加权：两处数字必须一致
- 论文题目 / 级别 / 作者排序 / 状态：两处必须一致
- 大创项目名 / 级别 / 角色 / 产出：两处必须一致
- 竞赛名称 / 奖项 / 级别 / 时间：两处必须一致
- 英语成绩：两处必须一致

**不一致的后果**：评审会质疑材料真实性，可能导致一票否决。

- `has_resume: true`：build.py 在 docx 第一页插入简历

### 14.2 "过度包装"判断标准

**量化指标超过行业常识 30% 即疑过度包装**：

| 指标 | 行业常识 | 过度包装阈值 |
|------|----------|--------------|
| 本科生一作 SCI 一区论文 | 极少见 | 1 篇以上需详细佐证 |
| 本科生一作 CCF-A 论文 | 少见 | 1 篇以上需详细佐证 |
| 国家级大创准确率提升 | 5~10pp | >15pp 需详细佐证 |
| 本科生发明专利授权 | 少见（多数在审） | 已授权需详细佐证 |
| 本科生代码量 | 1000~5000 行 | >10000 行需详细佐证 |
| 本科生 GPU 使用量 | 100~1000 卡时 | >5000 卡时需详细佐证 |

**判断原则**：评审会根据申请人所在学校、年级、导师水平评估指标合理性。指标过高反而引起质疑。

### 14.4 其他常见坑

- **个人陈述套模板**：套用网络范文直接淘汰，必须原创
- **科研经历含糊**：只写"参与"不写角色与产出，评审无法评估贡献度
- **推荐信栏空白**：即使推荐信未寄出也要写明推荐人信息
- **附件清单不全**：列 6~8 项，每项注明份数与盖章情况
- **个人陈述超字数**：>1800 字评审没时间看
- **长篇大论家庭背景**：与方向无关则不写；有关则 50 字以内带过
- **不提具体导师**：评审认为未做功课
- **加权平均分写法不规范**：必须含分母"91.5/100"
- **推荐人职称造假**：写真实推荐人，注明"已与推荐人确认同意"
- **三段比例失衡**：按 §2 字数四档版本化适配表执行
- **论文状态隐瞒**：注明"已录用，2024.10 见刊"或"已投，under review"
- **附件清单与正文不呼应**：PS 提到的成果必须有附件证明

## §15 金句模板（8 句）

### 15.1 金句 1：方向选择开篇（替代"从小就对"）

> "我对 [研究方向] 的兴趣，并非源于一时冲动，而是在 [项目名] 中连续投入 [X 个月] 后逐步确认的研究选择。"

**适用**：个人陈述第一段（学术基石）开篇。

**示例**：
> 我对自然语言处理的兴趣，并非源于一时冲动，而是在《基于对比学习的法律问答系统》大创项目中连续投入 12 个月后逐步确认的研究选择。

### 15.2 金句 2：本科科研痛点引出方向

> "本科阶段我在 [课题] 中遇到的 [具体困难]，让我意识到 [核心认识]——这一认识将成为我研究生阶段的起点问题。"

**适用**：个人陈述第一段（学术基石），从科研痛点自然过渡到方向选择。

**示例**：
> 本科阶段我在《低资源对话理解》课题中遇到的"标注数据稀缺导致表征不充分"困难，让我意识到低资源场景下的鲁棒表征是 NLP 核心问题——这一认识将成为我研究生阶段的起点问题。

### 15.3 金句 3：选校理由（替代"梦寐以求"）

> "选择 [学校] 不是因为 [排名/名气]，而是因为 [具体导师] 在 [具体问题] 上的工作直接回应了我本科研究中尚未解决的 [具体痛点]。"

**适用**：个人陈述第三段（未来展望）选校理由。**示例**：选择 XX 大学不是因为 CS Rankings 排名前列，而是因为 XX 教授在对比学习与知识蒸馏融合方向的工作直接回应了我本科研究中尚未解决的"低资源场景下表征不充分"痛点。

### 15.4 金句 4：导师对接（替代"师资雄厚"）

> "我已与 [导师] 就 [具体论文名] 进行 [N 次] 邮件沟通，老师建议我提前阅读 [论文名] 并复现核心代码，目前已完成 [复现进度]，正在跟进 [具体问题]。"

**适用**：个人陈述第三段（未来展望）导师对接段。**示例**：我已与 XX 教授就《Contrastive Learning with Knowledge Distillation》进行 3 次邮件沟通，老师建议我提前阅读其 2024 年 ACL 论文并复现核心代码，目前已完成 80% 复现进度，正在跟进温度参数 τ 的敏感性分析问题。

### 15.5 金句 5：跨方向申请解释

> "之所以选择 [研究方向] 而非本科主流方向 [原方向]，是因为在 [具体课程/项目] 中我发现 [具体观察]，这一观察促使我系统补强了 [具体能力] 并完成 [具体产出]。"

**适用**：跨方向申请时解释方向选择动机。**示例**：之所以选择自然语言处理而非本科主流方向嵌入式系统，是因为在《机器学习》课程中我发现表征学习对小样本场景的关键作用，这一观察促使我系统补强了 PyTorch 与深度学习理论，并完成《基于对比学习的法律问答系统》大创项目。

### 15.6 金句 6：研究生计划三步（替代"刻苦钻研"）

> "若能进入贵校 [实验室] 深造，我计划在研一完成 [课程清单] 与 [文献调研 X 篇]，在研二围绕 [具体研究问题] 推进实验，预期产出 [论文/系统量化指标]，长期目标是 [一句话职业规划]。"

**适用**：个人陈述第三段（未来展望）研究生计划。**示例**：若能进入贵校 XX 国家重点实验室深造，我计划在研一完成《深度学习》《统计学习方法》等核心课程与文献调研 50 篇，在研二围绕"低资源场景下的鲁棒表征"推进实验，预期产出 CCF-B 类会议论文 1 篇，长期目标是成为高校 NLP 方向研究者。

### 15.7 金句 7：材料真实性背书

> "以上经历均可由附件 [X~Y] 佐证；如需进一步材料或代码仓库链接，我可随时补充。"

**适用**：个人陈述结尾，增强真实性背书。**示例**：以上经历均可由附件 3~7 佐证；如需进一步材料或代码仓库链接（github.com/zhangsan/xx），我可随时补充。

### 15.8 金句 8：郑重表态（替代"倍感荣幸"）

> "我清楚 [院校] 的录取竞争激烈，若未获录取我将 [明确的备选路径]；但我仍希望以最郑重的方式表达对贵校 [项目] 的优先选择。"

**适用**：个人陈述结尾，郑重表态。**示例**：我清楚贵校计算机学院的录取竞争激烈，若未获录取我将参加预推免批次再次申请；但我仍希望以最郑重的方式表达对贵校 NLP 方向的优先选择。

### 15.9 金句使用注意事项

- 金句是模板，必须填入具体内容，不能直接照搬
- 同一篇个人陈述中金句不超过 3 句，过多显得套路
- 金句须与上下文自然衔接，不能突兀插入
- 金句中的占位符（[XXX]）必须替换为具体内容，不能保留占位符

## §17 红线规则与免责声明

### 17.1 红线规则（一票否决）

以下行为一旦发现，直接淘汰：

1. **个人陈述套模板**：含 §14 任意禁用词或与网络范文高度雷同
2. **学业硬指标不达门槛**：GPA/排名/英语任一不达标
3. **推荐信造假**：推荐人不知情或冒用他人名义
4. **论文/专利造假**：虚构作者排序或状态
5. **数据不一致**：简历与个人陈述数据矛盾
6. **过度包装**：量化指标超过行业常识 30%（§14.2）
7. **抄范文**：直接套用网络范文
8. **虚构导师沟通**：advisor_contact_status 与实际不符

### 17.2 真实性核查清单

提交前逐项核对：

- □ 所有数据真实可查（GPA/排名/论文/专利）
- □ 论文作者排序与录用通知一致
- □ 推荐人确已同意撰写推荐信（has_agreed=true）
- □ 大创项目立项书与结题证明齐全
- □ 竞赛获奖证书真实有效
- □ 论文/专利状态如实填写（不把在审写成已发表）
- □ 导师沟通进度如实标注（advisor_contact_status）
- □ 量化指标不超过实际成绩

### 17.3 内容核查清单

- □ 基本信息表 10 行齐全
- □ GPA 含分母，排名含基数，CET-6 ≥425
- □ 主修课程表 10~15 门，奖学金按时间倒序
- □ 科研经历四张子表（大创/论文/专利/竞赛）齐全
- □ 个人陈述按字数四档版本化适配（word_count_version）
- □ 个人陈述无禁用句（15 个）
- □ 推荐信情况含 2 位推荐人完整信息
- □ 附件清单 6~8 项，注明份数与盖章情况
- □ 个人陈述与科研经历呼应（不矛盾）
- □ 个人陈述与附件清单呼应（提到的成果均有附件证明）
- □ 论文级别缩写规范（SCI/CCF/EI/中文核心）
- □ 推免资格确认（已取得本校推免资格）
- □ 简历与个人陈述数据一致（has_resume=true 时）

### 17.4 格式核查清单

详见 §16.4 格式标准，提交前逐项核对：A4 页边距、宋体小四正文 1.5 倍行距首行缩进 2 字符、黑体三号一级标题、表格宋体五号居中表头加粗、中英文标点不混用、页码底部居中、封面黑体二号、序号体系一致。

### 17.5 附件清单完整性检查

| 正文提到的成果 | 必备附件 | 正文提到的成果 | 必备附件 |
|----------------|----------|----------------|----------|
| GPA / 排名 | 成绩单（教务处盖章） | 专利 | 受理通知书或授权证书 |
| CET-6 / TOEFL / IELTS | 英语成绩单复印件 | 大创项目 | 立项书 + 结题证明 |
| 论文（已发表） | 录用通知 + 见刊页面 | 竞赛获奖 | 获奖证书复印件 |
| 论文（在审） | 投稿确认邮件截图 | 推荐信 | 推荐人签字密封件 |
| 简历（has_resume=true） | 简历附在 docx 第一页或单独提交 | | |

### 17.6 学校差异处理

不同学校保研推免申请书模板有差异，按学校适配：

| 学校类型 | 推荐字数版本 | 适配方式 |
|----------|--------------|----------|
| 顶尖 985（清北复交） | 1500 字版 | 增设英文 PS 段落 |
| 普通 985 | 1000 字版 | 直接套用 |
| 211 院校 | 500 字版 | 调整字数区间 |
| 中科院系统 | 1800 字版 | 第三段扩展 + 自我评价段 |
| 海外高校 | 不适用 | 纯英文 PS + CV |

**5 校保研政策差异**：清华（前 5%/CET-6 ≥460/1500 字版/重科研计划）、北大（前 3%/TOEFL ≥100/1800 字版/重方向匹配）、复旦（前 10%/CET-6 ≥425/1000 字版/重综合素质）、上交（前 5%/CET-6 ≥425/1500 字版/重工程能力）、浙大（前 10%/CET-6 ≥425/1000 或 1500 字版/重交叉学科）。

### 17.7 适配步骤

1. 优先用目标院校下发的官方模板
2. 按官方模板字段顺序重新组织本 skill 生成内容
3. 字数与栏目微调以官方要求为准（按 §2 字数四档版本化适配表选择）
4. 检查官方是否有特殊栏目（如"获奖证明清单表""英语水平证明表"）
5. 本 skill 作为内容质量参考，不替代官方模板

### 17.8 通用提醒

- 不同渠道（夏令营/预推免/九推）材料要求不同，按 §11 差异表与渠道官方指南为准
- 同一学校不同学院要求可能不同（如计算机学院 vs 软件学院），按学院指南为准
- 按截止前 5~7 天完成关键节点（详见 §10），不要拖到截止前 3 天
- 电子版提交时按官方系统要求命名，不要使用默认文件名
- 系统填报型申请按 §11.3 与 §12 流程操作

### 17.9 免责声明

- 本 skill 生成的材料仅供内容质量参考，不替代官方模板
- 所有数据必须真实，申请人须对材料真实性负全部责任
- 推荐信代写须征得推荐人同意，最终须推荐人本人签字
- 导师套磁须遵守学术礼仪，不得骚扰
- 量化指标须符合实际，过度包装后果自负
- 本 skill 不保证录取结果，仅提供撰写规范与流程指导
- 目标院校政策如有变化，以官方最新通知为准
